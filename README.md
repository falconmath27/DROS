# Optimal Stopping with Memory — MAC F244 project

Course project for MAC F244 (Stochastic Calculus): replicate *Deep Recurrent Optimal
Stopping* (Damera Venkata and Bhattacharyya, NeurIPS 2023), extend it to American options
under rough volatility, and backtest learned exit timing across markets.
The paper and the team plan are in [`docs/`](docs/).

## Install and run

```bash
pip install -r requirements.txt
python -m pytest -q tests                  # 59 tests, about a minute
python -m experiments.benchmarks           # tree vs PDE ground truth, about 1 min
python -m experiments.run_parallel --threads 3 --max-procs 4   # E1-E5 in parallel
python -m experiments.run_all E1 E4        # or selected experiments, one after another
python -m experiments.summarize            # -> results/summary.md, tables.tex, replication_table.tex
python -m experiments.paired               # -> results/paired.md (paired differences)
```

`run_parallel` runs each experiment in its own process (results/raw_E?.jsonl and
results/logs/E?.log while running), then merges everything into results/raw.jsonl and
regenerates the summary and paired comparisons. E3 needs about 2.5 GB of memory at its peak.

Always run from this folder (the project root).

## The shared format (every problem, every method)

- `X`: shape `(N, H+1, d)`, features observable on path `i` at date `j`.
- `R`: shape `(N, H+1)`, reward for stopping at date `j`, **already discounted to date 0**.
- Each method has `fit(X_train, R_train, X_val, R_val)` and `stop(X, R) -> tau`;
  at date `j` it may use only `X[:, :j+1]` and `R[:, :j+1]` (checked by `tests`).
- Score: `common.problem.evaluate(R_test, tau)` = mean of `R_test[i, tau_i]`.
- `Problem.itm_only`: `True` for option payoffs, `False` for trading rewards that can be negative.

- Test-set standard errors: about 0.013 (E1), 0.16 (E2), 0.065 (E3), 0.06 (E4).
- E1, E3: OSPG-MLP is closest to the exact price (−0.12%, −0.05%, −0.44%), ahead of LSM and
  FQI (−0.9% to −1.6%), the paper's ranking; our errors match the paper's (0.07%, 0.23%).
- E2: all methods agree with Becker et al. within noise; the OSPG paper's own values are
  about 0.8 lower, below Becker's lower bound.
- Paired tests: OSPG-GRU trails OSPG-MLP by 0.1-0.5% on E1-E3 (z = 2.2-3.7). Memory costs a
  little when the problem has none.
- E4 (stand-in): both OSPG policies beat LSM, DOS and FQI-GRU (z = 2.3-4.5), but GRU = MLP
  (z = 0.3). The gain comes from avoiding backward induction, not from reading the
  history. P3 should re-check this with the real simulator and an H sweep.
- E5: no method beats holding, as optional stopping predicts for near-martingale prices.
- Run on 12 logical cores, with experiments running in parallel; training times in the
  summary are therefore only rough.

## For P5: per-path results

Every run saves the test-set reward and stopping date of each path to
`results/paths/<experiment>_<problem>_seed<seed>.npz`, with arrays `reward_<method>` and
`tau_<method>`. Within one file every method was evaluated on the same test paths, so
differences can be taken path by path:

```python
import numpy as np
z = np.load("results/paths/E4_rbergomi_put_seed0.npz")
diff = z["reward_OSPG-GRU"] - z["reward_LSM"]        # one value per test path
```

`python -m experiments.paired` gives the simple paired standard errors (independent
paths). For E5 the windows overlap in time, so use the block bootstrap by date instead;
`make_exit_windows` returns each window's start day for that.

## Implementation notes

- OSPG starts with output bias −2 (a "mostly wait" policy). Started near φ = 0.5 it
  converged to "stop immediately" on the in-the-money put (value 4.0 instead of 4.478).
- OSPG adds a small penalty (1e-3 × mean z²) on its pre-sigmoid outputs z and trains for at
  least 8,000 steps. Without it the GRU policy drove every stop probability to ~0, where the
  policy gradient (proportional to φ) vanishes, and it stalled at "never stop" on the
  d = 50 max-call (68.6 instead of about 70).
- OSPG-MLP uses batch normalisation on its input and hidden outputs, as in the paper, and
  switches to the training statistics (eval mode) whenever it makes decisions. The baselines
  run without it (`batch_norm=False`): it lowered FQI-MLP on the American put (4.426 and 4.442
  against 4.480 and 4.462 for seeds 0 and 1), so they keep their stronger setting.
- Networks predict in blocks of 8,192 paths, and the geometric-call problem is simulated in
  blocks with float32 features; the first run of E3 with d = 20 ran out of memory.
- Date 0 is decided the same way for every method: all simulated paths share one state
  there, so the immediate reward is compared with the value the trained rule achieves.
- All prices are out-of-sample (trained on one set of paths, evaluated on another), so they
  are lower bounds on the true price.
- The OSPG paper's own max-call numbers (about 50.9 for d = 20) are below Becker et al.'s
  lower bound (51.571), so we compare against Becker et al.
